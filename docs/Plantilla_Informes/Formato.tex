\section{Introducción}

RestGest Mateos es un producto de software web orientado a centralizar la gestión operativa de Restaurante Mateos, 
organización gastronómica de la ciudad de Ambato que trabaja con dos sucursales. El producto busca reemplazar y 
complementar registros manuales utilizados en la operación diaria mediante herramientas digitales para ventas, 
conteo de almuerzos y proteínas, menú configurable, inventario, gastos, reportes, indicadores y apoyo a la toma de decisiones.

La planificación detallada constituye la línea base para organizar el trabajo del equipo desde el \textbf{12 de agosto de 2026} 
hasta el \textbf{4 de noviembre de 2026}. El cronograma considera \textbf{61 días laborables}, con jornadas de lunes a viernes. 
La estructura se organiza en seis fases: Planificación y Análisis de Requisitos; Diseño del Sistema; Desarrollo del Sistema; 
Pruebas y Aseguramiento de la Calidad; Implantación y Despliegue; y Capacitación, Documentación y Cierre.

El presente informe consolida la Estructura de Desglose del Trabajo (EDT, conocida internacionalmente como WBS), las duraciones, las dependencias, los trabajos paralelos y secuenciales, los entregables, 
los recursos, el presupuesto, la calidad, las comunicaciones, los riesgos, las adquisiciones y los criterios de control. 
La planificación descrita en este documento constituye la línea base detallada del proyecto y prevalece, para efectos de ejecución 
y seguimiento, sobre estimaciones preliminares de tiempo realizadas antes de completar la descomposición del trabajo.

\section{Objetivos}

\subsection{Objetivo general}

Establecer la planificación integral del proyecto RestGest Mateos mediante la definición de alcance, fases, actividades, entregables, 
tiempos, dependencias, recursos, costos, criterios de calidad, comunicaciones y riesgos, con el fin de dirigir su desarrollo e 
implantación entre el 12 de agosto y el 4 de noviembre de 2026.

\subsection{Objetivos específicos}

\begin{enumerate}
    \item Descomponer el proyecto en fases y paquetes de trabajo verificables mediante una EDT, determinando para cada actividad su duración, fecha de inicio, fecha de finalización, predecesores y entregables.
    \item Asignar de forma coherente los recursos humanos, tecnológicos y económicos necesarios, identificando actividades paralelas y secuenciales para aprovechar la especialización del equipo y mantener el cronograma de 61 días laborables.
    \item Definir mecanismos de calidad, comunicación, gestión de riesgos, adquisiciones, aceptación y control de cambios que permitan monitorear el avance y asegurar la entrega funcional de RestGest Mateos dentro del alcance autorizado.

\section{Alcance}

El presente informe comprende la planificación del proyecto RestGest Mateos desde el \textbf{12/08/2026} hasta el 
\textbf{04/11/2026}, considerando el trabajo del equipo de proyecto y la participación del representante autorizado y usuarios 
designados de Restaurante Mateos.

El alcance documental incluye:

\begin{itemize}
    \item estructura de desglose del trabajo y seis fases del proyecto;
    \item cronograma detallado, hitos y relaciones de precedencia;
    \item definición de actividades paralelas y secuenciales;
    \item entregables por paquete de trabajo;
    \item asignación de responsabilidades y recursos;
    \item presupuesto operativo del proyecto;
    \item planificación de calidad, pruebas y criterios de aceptación;
    \item gestión de comunicaciones, riesgos, adquisiciones y cambios;
    \item planificación del piloto en la sucursal 2 y posterior despliegue para las dos sucursales;
    \item documentación, capacitación, aceptación y cierre.
\end{itemize}

La planificación funcional contempla usuarios y roles, sucursales, productos, categorías, menú diario configurable, conteo rápido, 
ventas, inventario, gastos, reportes, panel de control, indicadores y recomendaciones. El reconocimiento óptico de caracteres (OCR) se 
considera una funcionalidad de apoyo sujeta a validación técnica y revisión humana.

Quedan fuera del alcance inicial la contabilidad formal, facturación electrónica, declaraciones tributarias, nómina, ERP completo, 
plataforma bancaria, sistema integral de servicio de entrega a domicilio, gestión integral de servicio de alimentación para eventos y modelos predictivos avanzados sin historial suficiente. 
El consumo teórico por recetas permanece condicionado a que el restaurante disponga de porciones y recetas suficientemente estandarizadas.

\section{Método / Políticas / Contenido}

\subsection{Método de planificación}

La planificación se elaboró mediante un enfoque \textbf{por fases con ejecución técnica parcialmente paralela}. Las fases mantienen una 
secuencia macro obligatoria, mientras que dentro de cada fase se permite ejecutar actividades simultáneas cuando sus dependencias y 
responsables lo permiten.

El procedimiento aplicado fue:

\begin{enumerate}
    \item consolidar el alcance funcional y las exclusiones del producto;
    \item descomponer el trabajo mediante una EDT;
    \item identificar entregables verificables por actividad;
    \item estimar duraciones en días laborables de lunes a viernes;
    \item establecer relaciones de Fin a Inicio entre actividades dependientes;
    \item permitir paralelismo donde no existe restricción técnica;
    \item garantizar que el último proceso o hito de cada fase sea predecesor del inicio de la siguiente;
    \item asignar responsables según especialidad;
    \item establecer recursos, costos, calidad, riesgos, comunicaciones y adquisiciones;
    \item cargar la planificación en Microsoft Project para mantener niveles de sangría, predecesores y visualización temporal.
\end{enumerate}

La duración de cada actividad se expresa en \textbf{días laborables}. Los sábados y domingos no se contabilizan. Para esta línea base 
académica no se descuentan feriados.

\subsection{Políticas de planificación y control}

\begin{itemize}
    \item La línea base temporal inicia el 12/08/2026 y finaliza el 04/11/2026.
    \item Ninguna actividad puede iniciarse antes de cumplir sus predecesores definidos.
    \item Las actividades con el mismo predecesor pueden ejecutarse en paralelo cuando sus responsables y recursos lo permitan.
    \item El último proceso o hito de una fase actúa como puerta de control para la fase siguiente.
    \item Los cambios que afecten alcance, fecha final o presupuesto requieren análisis de impacto antes de incorporarse a la línea base.
    \item El código fuente se mantendrá en repositorio privado con control de versiones y revisión de cambios.
    \item El OCR nunca será fuente autoritativa de datos: todo reconocimiento debe ser revisable y corregible antes del registro definitivo.
    \item El despliegue completo se realizará después del piloto y de la corrección de incidencias prioritarias.
    \item Los entregables documentales se mantendrán versionados y con evidencia de elaboración, revisión y aprobación.
\end{itemize}

\subsection{Línea base del alcance}

El producto se organiza alrededor de la secuencia conceptual \textbf{Registrar - Relacionar - Analizar - Recomendar}. La línea base incluye:

\begin{itemize}
    \item autenticación, usuarios, roles y permisos;
    \item gestión de dos sucursales;
    \item productos, categorías, proteínas y menú diario configurable;
    \item conteo rápido de almuerzos, proteínas, extras y opciones;
    \item registro e historial de ventas;
    \item inventario con entradas, salidas, ajustes, stock y niveles mínimos;
    \item gastos por categoría y sucursal;
    \item reportes diarios, semanales, mensuales y por rango;
    \item reportes por sucursal, tipo de almuerzo y proteína;
    \item productos más vendidos;
    \item reportes de inventario, movimientos, ajustes y stock bajo;
    \item reportes de gastos y comparación entre sucursales;
    \item panel de control, indicadores y recomendaciones operativas;
    \item reconocimiento óptico de caracteres (OCR) asistido para tickets y notas, sujeto a validación técnica;
    \item piloto, despliegue, documentación, capacitación y aceptación.
\end{itemize}

\subsubsection{Recursos tecnológicos}

La arquitectura tecnológica se selecciona para minimizar el costo inicial sin comprometer la posibilidad de crecimiento. Se prioriza el uso de herramientas de código abierto, planes gratuitos y consolidación de servicios cuando sea técnicamente viable.

\begin{itemize}
    \item \textbf{Equipos de trabajo:} computadores portátiles personales del equipo y conexión a Internet.
    \item \textbf{Interfaz de usuario:} React 19, TypeScript, Vite, Material UI, TanStack Query, React Hook Form y Zod.
    \item \textbf{Servidor de aplicaciones:} NestJS sobre Node.js 24 LTS, servicios REST y documentación Swagger/OpenAPI.
    \item \textbf{Persistencia:} PostgreSQL 18 y Prisma. Inicialmente PostgreSQL podrá ejecutarse en el mismo servidor virtual de la aplicación para reducir costos; una base administrada se mantiene como alternativa de contingencia o crecimiento.
    \item \textbf{Seguridad:} tokens JWT, cookies con atributo HttpOnly, control de acceso basado en roles y Argon2id.
    \item \textbf{Infraestructura:} Docker, Nginx y un servidor virtual de DigitalOcean; el despliegue de la interfaz puede utilizar Cloudflare Pages cuando resulte conveniente.
    \item \textbf{Archivos y respaldos:} Cloudflare R2, sujeto al volumen real de almacenamiento.
    \item \textbf{Reconocimiento de documentos:} Google Cloud Vision para OCR, condicionado a la validación técnica y al control de consumo.
    \item \textbf{Gestión técnica:} GitHub, GitHub Actions y repositorio privado.
    \item \textbf{Diseño:} Figma.
    \item \textbf{Gestión del trabajo:} Trello.
    \item \textbf{Pruebas:} Vitest/Jest y Playwright.
\end{itemize}

\subsection{Gestión de cambios y seguimiento}

Toda solicitud que altere alcance, presupuesto, fecha final, dependencias críticas o criterios de aceptación deberá registrarse y 
evaluarse antes de modificar la línea base. La evaluación considerará:

\begin{itemize}
    \item descripción y motivo del cambio;
    \item actividades y entregables afectados;
    \item impacto en cronograma y ruta de dependencias;
    \item impacto en costo, calidad y riesgo;
    \item decisión de aceptar, diferir o rechazar;
    \item actualización de versión documental cuando corresponda.
\end{itemize}

El seguimiento utilizará el cronograma de Microsoft Project, Trello para trabajo operativo, GitHub para evidencia técnica y los informes 
de pruebas/piloto para control de calidad.
